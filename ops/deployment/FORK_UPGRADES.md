# 定制版本升级边界

已确认范围：移除主站版本弹层中的官方在线更新和回退操作，后端同时拒绝原地替换程序。避免官方二进制及其内嵌前端覆盖供应商管理接入、品牌等定制功能。

- `VersionBadge.vue` 固定为只读版本提示，保留版本刷新、新版本信息与更新日志链接；不再显示官方更新、重试、版本回退及官方镜像/安装脚本命令。
- 管理路由 `POST /api/v1/admin/system/update` 和 `POST /api/v1/admin/system/rollback` 在既有管理员认证、审计与合规校验之后，进入原有操作/幂等处理之前返回 HTTP 403，`reason=IN_PLACE_UPDATE_DISABLED`。旧页面直接调用、携带幂等键、指定版本或空请求均不能替换程序。
- 原有版本查询、检查更新、只读回退版本查询及重启接口保留；不改网关、供应商业务、数据库和权限模型。不增加运行时启用开关。
- 保留上游更新服务内部实现和不可达的原 UI 流程，定制策略仅位于组件分支与路由薄层；未来合并上游时需重点确认策略仍生效，不能只删除前端按钮。

## 升级与恢复

将上游变更合并到本仓库分支，处理冲突，回归主站及供应商功能；构建带明确提交标识的自有镜像，备份数据库与部署配置，再按已确认的发布流程部署。不要直接运行官方安装脚本或换成官方镜像。

保留上一版自有镜像和配置。发生数据库迁移时，恢复方案需同时考虑数据库兼容性或经过验证的备份恢复，不能默认换回镜像就能撤销迁移。本变更本身无数据库迁移；代码回退仅用于隔离验证，不应据此重新开放生产在线更新。

## 验收

1. release/source 构建、有/无新版本时，均无更新或回退操作及官方替换命令；非管理员仍只显示静态版本。
2. 管理员请求两个写接口均返回上述 403，且不调用更新/回退服务；既有外层认证不会被绕过。
3. 版本刷新、新版本号与日志链接保留，重启路由仍指向既有处理器。测试不实际下载、替换或重启程序。
4. 聚焦命令：前端 `pnpm exec vitest run src/components/common/__tests__/VersionBadge.fork.spec.ts`；后端 `go test -tags=unit ./internal/server/routes -run '^TestForkSystemRoutes$'`。本轮仅修改、验证代码，不自动提交、推送或部署。
