# 分组接入设置与账号直接接入

2026-10-23 用户批准：移除供应商业务中的“系统隔离组”，在主站分组创建/编辑页配置“允许供应商账号接入”；授权及必要校验成功后自动启用，无人工审核或放行步骤。本说明取代旧方案中隔离组、服务器白名单和“成功后永久暂停”的相应描述；不表示已部署。

## 行为与接口

- 创建 Anthropic 分组可勾选接入；已有分组在编辑弹窗独立读取/保存接入设置。独立保存按钮避免把跨服务的两次写操作伪装成原子操作。创建分组成功但接入设置失败时转编辑窗口，不重试创建分组。
- `GET/PUT /api/supplier/admin/v1/groups/{id}/access` 使用现有主站管理员 Bearer 或管理员 Cookie/CSRF，写请求校验 Origin；PUT body `{enabled:boolean,supplier_group_name?:string}`，`If-Match` 为读取到的版本（不存在时0）。冲突409；不允许非管理员写入。开启时服务端检查上游ID、Anthropic、active；已失效分组仍允许关闭。供应商分组名留空时回退主站分组名。
- `GET /api/supplier/admin/v1/groups/access` 返回所有实际分组的接入开关、版本和供应商分组名，供主站列表显示。多个实际 Anthropic 分组可以配置相同供应商分组名；供应商门户会去重显示，授权完成后将账号绑定到该名称对应的全部实际分组。
- 设置在供应商库 `group_access`，按 upstream instance + group ID 归属，版本控制；每次变更同事务追加实际管理员审计。主站分组 schema、公开/专属、倍率、用户扣费及供应商采购原价不变。
- 启动仅一次导入旧 `SUPPLIER_APPROVED_GROUP_IDS`；初始化标记和导入同事务，以后重启不会用旧环境变量覆盖管理员开关。该变量不再是持续配置源。默认无开放分组。关闭不移动/暂停已有账号；尚未完成的授权重新校验分组。
- 不再读取或要求 `SUPPLIER_QUARANTINE_GROUP_ID`。旧组和既有账号不自动删除、迁移或启用。历史 LegacyTestMode 代码只用于旧协议回归，生产不注册。

## 接入安全及兼容边界

1. 生成与完成授权时校验供应商身份、代理归属/有效性/容量及所选分组，保留state/PKCE、去重和幂等。
2. 主站账号创建API新增可选 `schedulable`；不传仍为true，现有消费者行为不变。通过已有管理员路由提供 `GET /api/v1/admin/accounts/creation-capabilities`。适配器先检查能力；旧主站不支持时在创建前拒绝，不退化为先可调度后暂停。
3. 直接在所选正式组中创建 `schedulable=false` 账号；读回核验平台、身份类型、组、代理和暂停状态。
4. 先持久化上游账号归属与“准备启用”操作检查点，再请求启用并读回核验，最后提交完成状态 `created_running`。这是接入内部的短暂暂停，不是人工审核。
5. 已知失败不启用；启用结果未知时尝试暂停，保留 `needs_attention`、账号/代理占用和检查点，不重放换码或创建。跨HTTP系统不能保证原子提交；进程恰在启用成功后中断，账号可能已运行，但已有持久化归属。必须依据真实主站状态核对未完成操作，不能把未知当成功或删除占用。暂停补偿失败也需人工核对。

## 发布及恢复（本次不执行）

先备份供应商库并显式执行011迁移，更新runtime-grants.sql授权，再发布带创建暂停能力的主站，然后发布供应商服务/前端；主站分组表无迁移。上线后管理员开启目标Anthropic组即可，不通过本次代码变更自动开启生产组或真实OAuth。

011后旧供应商二进制会拒绝未知迁移，不可直接回退旧模块；使用兼容011的修复版本，或维护窗口恢复匹配备份。保留旧组、账号和财务历史。测试及源码回退记录位于本次外部验收目录。

## 验收范围

覆盖开启/关闭/版本冲突/实际主体审计/种子只导入一次、非管理员与错误Origin拒绝、失效或非Anthropic分组不可开启、直接选组创建且初始不可调度、验证成功自动启用、未知创建不重放和未知启用补偿暂停。使用一次性本地PostgreSQL和合成上游；不以这些结果代替真实Claude授权与非零调用验收。


## 添加账号的可调默认参数（2026-10-24）

供应商在“添加账号 → 高级设置”调整参数，默认值不是锁定值或业务上限。并发默认100，会话限制默认开启且最大会话数100、空闲超时5分钟；RPM限制默认开启、15 RPM、三区模型，粘性缓冲留空沿用主站计算；5小时费用控制默认关闭，开启时必须填写正数费用上限，粘性预留默认10 USD（可以设为0）。并发及会话数可高于100。留空的有默认值字段在失焦时恢复显示默认值；负数、非整数及不合法RPM不会被静默截断。

`POST /api/supplier/v1/oauth/sessions` 兼容增加可选 `settings`：`concurrency`、`max_sessions`、`session_idle_timeout_minutes`、`base_rpm`、`rpm_strategy`、`rpm_sticky_buffer`、`window_cost_limit`、`window_cost_sticky_reserve`。`max_sessions:0` / `base_rpm:0` 表示明确关闭，不能当作未填写而补默认；未传字段使用默认。并发/会话/超时正整数上界为有符号32位整数，RPM与主站一致为1–10000；0仅用于明确关闭限制。新参数只作用于本次新账号，不批量修改已有账号。

013迁移只在供应商 `supplier_oauth_sessions` 增加 `account_settings` JSONB。生成授权时校验、规范化并冻结参数，参数纳入幂等请求摘要；同一幂等键改参数返回409。完成授权从数据库读回参数，在创建主站账号时将并发写入 `concurrency`，其他限制映射到主站现有 `extra` 字段。关闭的限制不注入主站 `extra`；不改主站调度、计费、权限或主库表结构。旧的未完成授权（013之前空JSON记录）保留并发100/会话100/超时5、RPM关闭的原行为；旧客户端不传 `settings` 的请求摘要仍兼容。

发布需先备份模块库并显式执行013迁移，再发布供应商后端和门户（主站内嵌页面也需随自有构建更新）。运行角色已有整表SELECT/INSERT权限，无新增表或角色权限。旧二进制拒绝未知迁移，不能只回退二进制；优先前向修复，必要时在维护窗口恢复匹配数据库备份。源码回退脚本仅用于副本验证，不是线上数据库降级脚本。

验收覆盖默认/自定义（包括高于100）/关闭/非法数值、多分组勾选去重、OAuth参数冻结、幂等冲突、数据库往返及主站创建请求。仅隔离数据库和合成上游验证，不代替真实Claude授权或带负载的限流调度验收。
